# ProductPulse Internal Incident API — Design

**Owner-directed MVP, 2026-10-30.** Depends on verified PostgreSQL adapter in stacked branch feat/postgres-problem-registry.

**Goal:** expose a small, testable REST facade for the future incident dashboard using open-source FastAPI. Avoid writing a router/auth framework.

**Boundary:** service-to-service only, **not public internet or human-review auth**. A nonempty, server-configured internal token is mandatory on every data endpoint. HMAC-safe constant-time comparison; no default credentials. Tenant scope is created by the trusted server config and never accepted from a client header/body. The caller must be trusted to submit redacted ticket payloads and cannot make incident approval, merge/split or Jira writes.

**Endpoints:** GET /health/live (process only); POST /internal/v1/tickets (CanonicalTicketV1, extra forbidden, return ProblemRecord); GET /internal/v1/problems (active scoped records); GET /internal/v1/problems/{problem_id} (scoped ID, 404 if absent); GET /internal/v1/audit (no raw ticket bodies). No pair-label/approval endpoints.

**OSS:** FastAPI, Starlette TestClient / httpx, Uvicorn, existing Pydantic 2 and SQLAlchemy 2. Typed responses and OpenAPI generated by FastAPI; no hand-written swagger or auth/session stack.

**Acceptance:** HTTP no-token and wrong-token rejected, proper token works, client cannot override tenant scope, valid ticket persists through PostgreSQL and duplicate POST does not double-count; cross-scope not visible, nonexistent problem returns 404, audit never exposes body, no untrusted merge endpoint. Tests must run against actual PostgreSQL service and on Python 3.11/3.13. No public RBAC production claims.

**Next:** user authentication/OIDC and reviewer identity, real UI based on OSS shadcn/ui + TanStack Query + Recharts and Problem Registry persisted domain endpoints.
