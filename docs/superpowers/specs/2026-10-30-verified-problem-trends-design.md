# Design: проверяемые временные сигналы Problem (Phase 19A)

**Статус:** реализация в Draft PR #19; архитектурное решение пока не одобрено независимым reviewer. Не сливать в `main` до проверки.

## Цель
Показывать команде продукта наблюдаемую динамику обращений, относящихся к одному **явно объединённому** Problem, без подмены текстового сходства доказанным инцидентом.

## Источники доверия
- Нормализованные и предварительно очищенные `CanonicalTicketV1` с `created_at`.
- Только активный `ProblemRegistry` с явно выполненной операцией `merge` после проверки независимыми reviewers. Одного `pair_approved` недостаточно.
- Scope берётся из конфигурации backend, не из HTTP.
- История поступления данных, полнота загрузки и watermark **не известны** текущей версии. Их нельзя восстановить по первому/последнему тикету.

## Контракт
`ProblemTimeline` содержит текущий состав Problem, event-time, список исходных систем и опциональные сведения `SourceCoverage(source_system, complete_from, complete_through, evidence_ref)` от проверенного адаптера. Текущий `ProblemRegistry` сознательно передаёт пустые `coverage`: этот контракт пока не подключён к настоящему source importer.

Окна UTC: `[as_of-2W,as_of-W)`, `[as_of-W,as_of)`. Пороговые значения по умолчанию: 3 текущих обращения и увеличение на 2. Это абсолютный рост количества, **не статистически достоверная аномалия**.

Если хотя бы у одного обращения нет корректного времени или время позже `as_of`, статус `insufficient_timestamps`. Если рост наблюдаем, но у любого исходного source нет подтверждённой полноты на всем диапазоне, статус `unknown_coverage` + `observed_pattern`; результат **не подходит для автоматической эскалации**. Полнота по нескольким источникам — конъюнкция подтверждений каждого источника. `eligible_for_alert=false` для всех результатов этого этапа.

## Альтернативы и trade-offs
- Встроенный детерминированный расчёт вместо LangGraph/LLM, потому что арифметика событий не требует генеративной модели.
- JSONB snapshot пригоден для небольшой демонстрации (cap 5000), **не** для online analytics 66k+.
- Самый ранний сигнал находится в другом workflow — **неподтверждённые кандидаты BM25**. Объединять его с подтверждёнными Problem нельзя. Для будущего TTAI будут отдельно измерены ожидание разметки, merge и выдача предложения.

## Не входит в PR #19
Автоматическое создание Jira, уведомления, ML confidence, root cause, полнота организаторского dataset, source-watermark importer, честный historical replay по времени поступления, ранние pre-review предупреждения и доказательство ROI.

## Приёмка
TDD RED/GREEN на Python 3.11/3.13 и реальном PostgreSQL16; OAuth scope denial; UTC boundary/offset; ошибки времени; split; confirmed merge; unknown coverage; отсутствие мутаций audit/внешних writes; review комментарии и исправления документируются. Внешний reviewer обязателен до merge.
